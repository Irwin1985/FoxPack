# foxpack

FoxPack: libraries for VFP projects, downloaded from GitHub at a fixed version

Libraries are installed into lib\<library>\ of the project and recorded in
foxpack.lock with the exact commit and the SHA-256 of every file. Commit
both to git.

## Usage

```
foxpack <command> [options]
```

| Command | What it does |
|---|---|
| [`add`](#add) | Install a library into lib\ and record it in foxpack.lock |
| [`restore`](#restore) | Download exactly what foxpack.lock says |
| [`update`](#update) | Move one library (or all of them) to its latest version |
| [`remove`](#remove) | Remove a library from lib\ and from foxpack.lock |
| [`list`](#list) | List the installed libraries, with version and commit |
| [`verify`](#verify) | Check that the copies in lib\ are the ones in foxpack.lock |

## Examples

```
foxpack add jsonfox
```

## Commands

### add

Install a library into lib\ and record it in foxpack.lock

Without a version, the latest tag of the repository. A repository that
is not in the index (github:user/repo) is installed only after you
confirm it.

```
foxpack add <library> [opciones]
```

**Arguments**

| Argument | Type | Description |
|---|---|---|
| `library` | text, required | jsonfox, jsonfox@13.1 or github:user/repo |

**Options**

| Option | Type | Description |
|---|---|---|
| `-p`, `--project` | text, default `.` | Project folder |
| `-y`, `--yes` | flag | Confirm without asking (for scripts) |

**Examples**

```
foxpack add jsonfox@13.1
foxpack add github:user/mylib --yes
```

### verify

Check that the copies in lib\ are the ones in foxpack.lock

A library's copy is never edited: the fix goes to its repository.
This command is what watches for it.

```
foxpack verify [opciones]
```

**Options**

| Option | Type | Description |
|---|---|---|
| `-p`, `--project` | text, default `.` | Project folder |

**Exit codes**

| Code | Meaning |
|---|---|
| 12 | Some copies differ: it says which ones |

## What the host handles

FoxCli handles these options before reaching the CLI's code, and they work the same in every command.

| Option | What it does |
|---|---|
| `--help`, `<command> --help` | The general help, or that of a command |
| `--version` | The version of the CLI and of the host |
| `--format json`, `table` or `plain` | The output format. By default: `table` with a console in front and `plain` when the output goes to a file; `json` only when asked for |
| `describe` | The command schema in JSON, so an agent or a tool can discover the CLI |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | The command finished well |
| 1 | The command failed without saying more: it returned `.F.` |
| 2 | The command line is not valid: an unknown command, an option that does not exist, a value that is not of the declared type or a missing required argument. Nothing is run |
| 3 | The VFP component the CLI carries could not be activated |
| 4 | Internal host failure |
| 130 | Cancelled with Ctrl+C |
| 10 | The library or the version does not exist |
| 11 | Download failed (network, GitHub, a missing file) |
| 12 | A copy in lib\ does not match foxpack.lock |
| 13 | The repository has no valid foxpack.json |
| 14 | The folder is not a project, or foxpack.lock cannot be read |

The codes of each command are in its own section.
